# FRECS FAQ Chatbot 🦖

Інтелектуальна діалогова система (FAQ-чат) для факультету радіофізики, електроніки та комп'ютерних систем (РЕКС) Київського національного університету імені Тараса Шевченка. 

Проєкт побудований на базі архітектури **Advanced RAG** (Retrieval-Augmented Generation) та використовує методи семантичного пошуку, векторні бази даних і великі мовні моделі (LLM) для автоматизованого надання точних відповідей на запитання абітурієнтів та студентів.

## 🌟 Основні можливості
* **Семантичний пошук:** Розуміння суті запиту, а не лише ключових слів (завдяки векторним ембеддингам FastEmbed).
* **Інтелектуальна маршрутизація:** Автоматичний вибір між пошуком у локальній базі, парсингом у реальному часі та веб-пошуком.
* **Live-parsing:** Отримання актуальних розкладів та графіків сесій безпосередньо з сайту факультету в реальному часі.
* **Fallback Web Search:** Резервний пошук в інтернеті через DuckDuckGo, якщо інформації немає у локальній базі.
* **Система зворотного зв'язку:** Можливість ставити лайки/дизлайки відповідям, що впливає на динамічне переранжування результатів.
* **Адаптивний UI:** Сучасний клієнтський інтерфейс (Glassmorphism) із підтримкою світлої/темної тем та збереженням історії діалогу.

## 🛠 Технологічний стек
* **Backend:** Python, FastAPI, Uvicorn
* **Векторна БД:** Qdrant Cloud
* **Embeddings:** FastEmbed (`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`)
* **LLM:** Groq API (`llama-3.3-70b-versatile` та `llama-3.1-8b-instant`)
* **Web Scraping:** BeautifulSoup4, Requests
* **Frontend:** HTML5, CSS3, Vanilla JavaScript

## 🚀 Як запустити проєкт локально

### 1. Клонування репозиторію
```bash
git clone <URL_вашого_репозиторію>
cd <назва_папки>
2. Створення віртуального середовища та встановлення залежностей
Bash
cd backend/  
python -m venv .venv

# Активація (Windows):
.venv\Scripts\activate

# Активація (Linux/Mac):
source .venv/bin/activate

pip install -r requirements.txt
3. Налаштування змінних оточення
Створіть файл .env у папці backend/ та додайте ваші API ключі:

Фрагмент коду
QDRANT_URL=ваша_адреса_кластера_qdrant
QDRANT_API_KEY=ваш_ключ_qdrant
GROQ_API_KEY=ваш_ключ_groq
USE_LLM=True
4. Індексація бази знань
Перед першим запуском необхідно завантажити дані у векторну базу Qdrant:

Bash
python scripts/index_faq.py
python scripts/index_site.py
5. Запуск сервера (Backend)
Bash
uvicorn app.main:app --reload
Сервер запуститься за адресою: http://localhost:8000

6. Запуск клієнта (Frontend)
Відкрийте файл frontend/index.html у вашому браузері або скористайтеся розширенням Live Server у VS Code.

📂 Структура проєкту та опис файлів
Проєкт розділено на клієнтську та серверну частини з чіткою архітектурою.

⚙️ Бекенд (/backend/app/)
Головна бізнес-логіка, RAG-каскад та API сервіси.

main.py — Точка входу FastAPI. Містить конфігурацію CORS, підключення роутерів та Middleware для логування або профілювання.

config.py — Модуль для завантаження та валідації змінних оточення (з файлу .env).

schemas.py — Pydantic-моделі (схеми) для строгої типізації вхідних запитів та відповідей (наприклад, QueryRequest, ChatResponse).

Директорія /api/:

chat.py — Контролери (ендпоінти) API. Приймає HTTP-запити від фронтенду (/api/chat, /api/chat/feedback) та передає їх у сервіси.

Директорія /services/:

chat_service.py — Головний оркестратор RAG-каскаду. Керує маршрутизацією запитів (перевіряє привітання, викликає векторний пошук, активує веб-пошук при провалах).

embeddings.py — Ініціалізація та налаштування моделі векторизації FastEmbed. Відповідає за перетворення тексту на 384-вимірні вектори.

llm_service.py — Інтеграція з Groq API (LLM Llama). Містить логіку переформулювання запитів (Query Rewriting) та синтезу фінальних відповідей.

qdrant_service.py — Клієнт для роботи з хмарною БД Qdrant. Виконує векторний пошук, фільтрацію та оновлення лічильників (лайк/дизлайк) у Payload.

retrieval_service.py — Сервіс пошуку та переранжування результатів (Reranking). Оцінює релевантність знайдених чанків.

site_crawler_service.py — Модуль живого парсингу (Live-parsing) сайту факультету за допомогою BeautifulSoup4.

web_search_service.py — Резервний веб-пошук (Fallback) через DuckDuckGo API.

Директорія /utils/:

greetings.py — Евристичні правила для швидкого розпізнавання стандартних привітань без звернення до LLM.

text_splitter.py — Логіка нарізки великих текстів на чанки (Chunking) із перекриттям (Overlap) для збереження контексту.

🗄️ Дані та Скрипти (/backend/data/, /backend/scripts/)
data/faqs.json — Статичний файл із заздалегідь підготовленими питаннями/відповідями факультету (локальна база знань).

scripts/index_faq.py — Скрипт для пакетної векторизації даних з faqs.json та їх завантаження у колекцію faq_collection бази Qdrant.

scripts/index_site.py — Скрипт для автоматичного парсингу, генерації контекстних питань через LLM, векторизації та завантаження вебсторінок факультету в site_collection.

scripts/check_links.py, check_site_collection.py, test_site_search.py — Допоміжні скрипти для тестування пошуку та перевірки цілісності бази даних.

🖥️ Фронтенд (/frontend/)
Користувацький інтерфейс (SPA), який працює безпосередньо в браузері.

index.html — Головна розмітка інтерфейсу чат-бота (вікно діалогу, стартовий екран, панель вводу).

styles.css — Стилі проєкту. Реалізація ефектів Glassmorphism, анімацій, та адаптивності для мобільних пристроїв. Підтримка темної та світлої тем.

script.js — Клієнтська бізнес-логіка: надсилання асинхронних запитів (Fetch API) на бекенд, збереження історії чату в LocalStorage, динамічний рендеринг повідомлень та обробка лайків/дизлайків.

*.png (logo, nlo, rocket) — Графічні активи та іконки інтерфейсу.

svg_*.txt — Файли, що містять код SVG-анімацій для вступного екрана та декоративних елементів фону.

📄 Кореневі файли
requirements.txt — Перелік Python-бібліотек та їх версій, необхідних для роботи сервера.

.env (не відстежується в git) — Файл секретів (API ключі).

.gitignore — Правила для системи контролю версій Git (виключає .venv, .env, __pycache__ тощо).
